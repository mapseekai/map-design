# Local data and cleanup

## Choose the data root

`MAP_DESIGN_DATA_DIR` selects daemon-owned data. Set it before startup and restart
the daemon when changing it. Direct source startup defaults to `.map-design` in
the daemon working directory; `tools-dev` starts it from the repository root.
The packaged launcher defaults to `<namespaceBaseRoot>/<namespace>/data` and
requires an absolute path for an explicit override (a leading `~` is expanded).

```bash
export MAP_DESIGN_DATA_DIR="$HOME/MapDesignData"
pnpm tools-dev start
```

Changing the path selects a different store; it does not move existing projects.
Do not run unrelated daemons against the same data directory.

## Directory contents

| Path | Purpose | Cleanup effect |
| --- | --- | --- |
| `map-design.sqlite`, `-wal`, `-shm` | SQLite projects, conversations, revisions and run history | Removing these loses persisted state; back up the complete stopped store |
| `map-design-config.json` | Local settings and provider credentials | Removing it resets saved configuration and credentials |
| `mapdesign/` | Project-owned styles, resources, reports and other blobs | Required by the database's project records |
| `cartography-drafts/`, `cartography-edits/` | Generated document drafts, editing sessions and agent working directories | May contain unsaved document work |
| `runtime-tests/` | Working files used for local model checks | Generated by explicit model tests |

Lifecycle tools also keep process logs and caches outside this root. Packaged
apps have separate namespace `logs`, `cache`, `runtime` and Electron `user-data`
paths. Deleting the daemon data root does not remove those or uninstall the app.

## Staged skills

`.map-design-skills/` lives under an agent run's working directory, which may be
a selected project directory or a daemon-managed directory. It holds working
copies of bundled skills. The editable source is under the repository's
`skills/` directory. Stop related runs before removing staged copies; later runs
can recreate them. Staged skills are independent of Git worktree registration.

## Backup and reset

1. Stop the relevant runtime: `pnpm tools-dev stop` for source development, or
   quit the packaged app and wait for its daemon to stop.
2. Copy the complete data root, preserving access permissions. It contains
   local credentials as well as project data. Do not copy only the SQLite main
   file while a writer can still be using its WAL.
3. To reset all local projects and settings, remove that specific data root
   after confirming its contents are no longer needed. Restarting creates a
   new empty store; it does not recover deleted projects.

Removing `.map-design-skills/` only removes staged skill copies. Removing
`.map-design/` removes the default source data store when no override was used.
Both names are ignored by Git, but being ignored does not make data disposable.
