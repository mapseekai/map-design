# MapDesign 使用说明

MapDesign 是一个本地优先的地图设计工作台。它把地图预览、自然语言制图、可视化样式编辑、制图规范和版本记录放在同一个项目中。你可以从已有地图开始，描述希望呈现的效果，让 AI 调整图层，再通过地图交互和样式代码细化结果。

本文面向日常使用者，也提供开发环境和命令行的操作示例。功能与操作入口按 2026-09-26 的项目代码核对。

## 1. 能力一览

| 想完成的工作 | MapDesign 提供的能力 | 从哪里开始 |
| --- | --- | --- |
| 看一张在线地图 | 粘贴公开 MapLibre Style URL，交互预览地图 | 首页的地图地址输入框 |
| 创建可编辑地图 | 从 Style、GeoJSON、TileJSON、PMTiles 地址导入项目，保存本地草稿 | 首页创建表单或 `md project create` |
| 用文字调整地图 | AI 检查图层、修改样式、验证结果、请求预览和提交版本 | 项目中的会话区 |
| 连续安排修改 | 在当前会话排队发送需求，编辑或移除待发送项，按顺序执行 | 会话输入框与消息队列 |
| 指定地图上的修改目标 | 拾取要素，按单个要素、属性匹配或整个图层添加评论 | 地图评论工具 |
| 提供视觉与文本参考 | 附加当前视口截图和 UTF-8 文本文件 | 地图相机按钮、会话附件入口 |
| 手动细调样式 | 拾取要素并修改颜色、透明度、线宽、圆半径和文字大小 | 地图铅笔按钮 |
| 编辑完整样式 | 查看与编辑 `style.json`，通过校验后自动保存并更新地图 | 预览 / 代码切换 |
| 保存和比较阶段成果 | 提交地图版本、浏览历史、将历史样式恢复为当前草稿 | 版本面板 |
| 复用制图风格 | 导入、生成、编辑和下载 `CARTOGRAPHY.md`，创建项目时选用 | 制图规范库 |
| 选择 AI 执行方式 | 使用本地 agent，或保存多个 API 模型配置并按会话选择 | 设置、创建表单、会话运行时选择器 |
| 自动化操作 | 查询项目和运行状态、创建项目、提交需求、取消任务 | `md` CLI 与本地 daemon API |

## 2. 启动工作台

### 使用桌面应用

打开 MapDesign 后，从首页创建或进入项目。桌面端可以通过“选择工作目录”指定项目关联的本地目录。项目、会话、地图草稿和运行记录由本地 daemon 统一保存。

### 从源码启动

项目使用 Node.js 24 和 pnpm 10.33.2。以下命令在仓库根目录执行；使用 nvm 时，先载入 nvm，再让 `.nvmrc` 选择 Node 版本。

```bash
source "$HOME/.nvm/nvm.sh"
nvm use
node --version
corepack enable
pnpm install
pnpm tools-dev start
pnpm tools-dev status
```

`node --version` 应显示 `v24.x`。`tools-dev start` 管理 daemon、Web 和桌面开发进程；`status` 给出当前服务状态与访问地址。浏览器端打开状态输出中的 Web 地址。

常用管理命令：

```bash
pnpm tools-dev status
pnpm tools-dev logs
pnpm tools-dev restart daemon
pnpm tools-dev stop
```

更新 daemon 源码后，可以先构建再重启，让正在运行的服务加载新代码：

```bash
pnpm --filter @mapseekai/daemon build
pnpm tools-dev restart daemon
```

## 3. 配置 AI 运行时

### 3.1 使用 API Model

在 **设置 → 运行时 → API Model** 中添加具名模型配置。每张配置卡保存名称、模型 ID、接口协议、地址和凭据。这样可以为不同任务准备不同模型，也可以为同一模型保存不同服务地址。

1. 点击“添加模型”，填写便于识别的名称，例如“日常制图”。
2. 选择 OpenAI 兼容协议或 Anthropic 协议。OpenAI 配置可选择 Chat Completions 或 Responses。
3. 填写模型 ID、API Key 和需要使用的 Base URL。Base URL 可以填写服务的 API 前缀，例如 `https://api.example.com/v1`。
4. 对提供免密访问的本地兼容服务，可关闭“需要 API Key”。
5. 点击“保存模型”。
6. 点击“测试连接”，检查一次基础文本响应，查看测试时间和延迟。
7. 根据习惯将其中一项设为默认模型。

地图编辑任务使用具备工具调用能力的模型；截图任务选择具备图像输入能力的模型。连接测试会发送一次小规模模型请求，费用按所用服务计费。

已保存配置会出现在首页和会话的模型选择器中。API Key 保存在本地 daemon 的配置中，界面用凭据状态表示已保存的密钥。修改已有配置时，留空密钥字段可以保留原值；更换接口地址或协议时重新填写对应凭据。

### 3.2 使用本地 agent

先在本机准备并登录所选 agent CLI，再让 MapDesign 检测可用运行时。当前具备原生地图工具适配器的运行时包括：

| 运行时 | ID | 执行方式 |
| --- | --- | --- |
| API Model | `api` | daemon 内调用已配置的模型服务 |
| Codex | `codex` | Codex app-server 会话 |
| Pi | `pi` | Pi SDK 适配器 |
| Oh My Pi | `oh-my-pi` | Oh My Pi RPC |
| OpenCode | `opencode` | OpenCode 工具插件 |
| DeepSeek Harness | `deepseek-harness` | 专用运行配置和工具协议 |

界面根据本机检测、原生工具探测和模型目录显示可选项。选择运行时时，再按该运行时提供的选项设置模型、推理等级和服务档位。本地 agent 在项目工作目录内以当前用户身份运行。

也可以查询 daemon 返回的检测信息：

```bash
export MAP_DESIGN_DAEMON_URL="http://127.0.0.1:7456"
md agents list --json
```

实际 daemon 地址以 `tools-dev status` 输出为准。源码环境也可通过 `node apps/daemon/bin/md.mjs` 调用相同 CLI 入口。

### 3.3 在会话中选择模型

每个会话保存自己的运行时选择。当前项目任务结束后，在会话输入区切换 agent 或 API 配置，后续需求即按新选择执行。历史消息保留原来的执行来源，项目地图继续使用同一份草稿和版本历史。

开始执行时，系统会记录本轮所选运行时与模型；API 任务同时捕获本轮服务配置。运行中的任务继续使用已选配置。对于本地 agent，相同会话、agent、模型和工作目录下的后续任务可利用保存的原生会话继续工作。

## 4. 创建第一张地图

### 4.1 先预览地图

在首页“公开地图地址”中粘贴一个公开可访问的 MapLibre Style URL，例如：

```text
https://demotiles.maplibre.org/style.json
```

稍等片刻即可在首页缩放、平移并观察地图。选择允许浏览器跨域访问的 Style、瓦片、字体和 sprite 资源，可获得完整预览。

### 4.2 创建项目

1. 填写项目名称，例如“城市步行底图”。
2. 填写地图源地址。项目导入接受 Style、GeoJSON、TileJSON 和 PMTiles URL；首页即时预览以 Style URL 为入口。
3. 填写设计需求，说明用途、关注对象、颜色和观察尺度。
4. 选择运行时和模型。
5. 选择一份 `CARTOGRAPHY.md`。也可以使用内置 Quiet Atlas 制图规范。
6. 桌面端可选择项目工作目录。
7. 点击“创建地图设计”，等待地图导入和首轮设计任务。

示例需求：

> 为城市步行导览设计一张浅色底图。使用暖白背景、柔和蓝色水系和浅绿色公园；突出步行道路与街区轮廓。在城市级视野保持画面简洁，在街道级视野清楚展示道路名称。检查图层后分批调整，完成后验证并生成预览。

导入过程保存项目和可编辑地图样式；公开瓦片、字体和图标按需从其地址加载。首轮需求随项目保存，地图准备完成后进入执行。后续可从首页项目列表重新打开项目。

## 5. 在会话中完成制图

### 5.1 怎样表达需求

把任务写成“对象 + 修改目标 + 使用场景 + 验证方式”，AI 更容易定位图层并交付可检查的结果。

| 任务 | 可以直接发送的示例 |
| --- | --- |
| 了解地图 | “检查当前地图，列出道路、水系、绿地和文字图层，说明主要视觉层级。” |
| 调整主题 | “采用暖白底色和低饱和配色，让水系与公园清晰可辨，保留道路层级。” |
| 调整道路 | “把主干路描边调深，适当增加线宽，并保留次干路和支路的差异。” |
| 调整标签 | “检查城市级与街道级标签密度，突出重要地名，保持字号层级一致。” |
| 统一设计 | “按当前 CARTOGRAPHY.md 检查颜色、线宽和字体，并修正偏离规范的图层。” |
| 完成一轮 | “验证当前草稿，生成预览，说明修改的图层和检查结果，然后提交一个版本。” |

每轮任务会获得当前地图上下文、当前会话历史、所选制图规范、相关附件和自定义指令。你可以继续追问原因、缩小修改范围，或在新会话中讨论另一种设计方向。

### 5.2 观察执行过程

会话中会展示文本回复、运行状态和工具活动。展开工具活动可查看本次检查或修改的摘要。不同运行时提供的分析摘要也会按统一消息结构展示。

地图侧显示当前草稿与预览状态。完成重要修改后，检查目标区域和多个缩放级别，再保存阶段版本。一个具体工作流程是：

```mermaid
flowchart LR
  A[描述设计需求] --> B[检查地图与图层]
  B --> C[应用样式修改]
  C --> D[验证与预览]
  D --> E[观察地图]
  E --> F[提交版本]
  E --> A
```

### 5.3 连续发送与消息队列

当前会话执行任务时，可以继续输入下一步需求。新消息进入待发送队列，前一轮结束并完成连接清理后，队列继续发送下一项。

实时连接中断后，页面会定期查询任务与会话状态；连接恢复后自动同步执行结果，成功完成的任务会继续带动下一条排队消息发送。

例如可以顺序安排：

1. “先统一背景、水系和绿地颜色。”
2. “再调整道路层级和线宽。”
3. “最后检查文字标签，生成预览。”

待发送项可以编辑和移除。正在编辑队列项时，自动发送会暂时等待。队列随当前打开的会话工作区保留，已经受理的消息则进入本地持久化历史。长任务清单可另存为文本附件，便于后续继续引用。

点击停止会请求取消当前任务并暂停队列。任务失败或取消后，待发送项保持可检查状态；整理需求后点击继续发送。

### 5.4 多会话与项目调度

同一项目可以创建多个会话，例如分别讨论整体配色、道路层级和文字布局。会话各自保存消息与运行时选择，并共同使用项目地图。

同一项目按顺序执行 AI 制图任务，使地图修改有明确顺序。当前页面切换到另一个会话时，原会话的活动任务仍由工作区保持。不同项目由 daemon 分别管理运行状态，可以各自开展任务。

任务超时后，系统及时保存结果并收回本轮工具授权，同时等待 Agent 完成停止和资源清理，再释放项目执行位置。应用关闭也会等待这些清理过程。

### 5.5 项目与规范标签页

打开项目或制图规范编辑器后，顶部显示对应标签页，可以切换或关闭。打开的标签页在当前页面内保存未发送的输入文本及路由位置；关闭标签页或刷新页面会清除这些内存状态。

切换到其他工作区时，原工作区的地图和订阅会释放。会话内队列的保留范围是仍挂载的项目工作区，不能把它当作跨项目标签页或刷新后仍持久化的任务列表。已经被 daemon 受理的任务和消息独立保存，关闭标签页不会删除项目。

## 6. 用地图目标和附件表达意图

### 地图评论

1. 打开地图评论工具。
2. 点击地图要素；也可以聚焦地图后按 Enter，拾取视口中心附近的要素。
3. 多个要素重叠时，选择实际目标。
4. 选择作用范围：当前要素、按属性匹配的同类要素，或整个样式图层。单要素定位使用数据源提供的稳定要素 ID。
5. 写下修改要求并保存评论。
6. 立即发送，或选中多条评论后一次提交。

例如，选中一条道路后写“增强这类道路的边界对比”，比单独在聊天中描述位置更明确。每次可以合并发送最多 20 条评论；评论面板记录草稿、提交和运行结果。

### 地图截图

地图上方的相机按钮捕获当前视口 PNG，并放入当前会话的待发送附件。截图同时记录捕获时的地图版本和视口信息。

发送前可以查看和移除缩略图，每条消息可附加最多 4 张截图。使用 Codex、Pi、Oh My Pi、OpenCode 或 API Model 的图像输入通道，并选用具备视觉能力的模型，可以围绕具体画面讨论颜色、密度和视觉平衡。已发送截图随消息保留。

### 文本附件

通过会话附件入口附加 UTF-8 文件，例如设计简报、字段说明、分类清单、Markdown 或 JSON 参考。每条消息可附加最多 4 个文件，单文件 64 KiB，总量 128 KiB。

给出附件用途有助于 AI 正确使用内容，例如：“按附件中的分类名称检查道路图层，并解释每类对应的样式。” 后续会话会在上下文预算内继续引用近期附件。

## 7. 直接编辑地图样式

### 7.1 拾取要素并调整

打开地图铅笔工具，选择要素及作用范围。可用控件随图层类型变化，包括颜色、透明度、线宽、圆半径和文字大小。

拖动控件时地图即时预览。点击“保存”后，系统验证并写入草稿；点击“取消”恢复本次操作前的值。按属性匹配可以同时调整一类要素，整层范围适合统一图层风格。

对使用表达式的属性，界面用占位状态表示其原有计算逻辑；修改某个控件时，其余属性保持原值。进入当前草稿、待项目任务结束后，即可继续直接编辑。

### 7.2 编辑 style.json

在地图区切换到“代码”，查看完整 `style.json`。编辑后短暂停顿，系统检查 JSON 和样式结构，校验通过即保存草稿并更新预览。

状态栏展示待应用、保存中、校验结果和冲突提示。遇到其他操作推进地图版本时，编辑器会保留你的文本，供你比较并决定如何继续。需要重新以当前项目状态为基础时，使用重新加载操作。

这种方式适合精确调整表达式、缩放范围、过滤条件和图层顺序；地图预览适合随后观察效果。

## 8. 保存版本与回看设计

地图草稿承载连续修改，已提交版本记录阶段成果。版本面板展示版本号、提交时间和样式摘要，可用于比较设计过程。

一次完整的版本保存流程：

1. 完成当前修改。
2. 让 AI 验证草稿并生成预览，观察实际地图。
3. 在对应预览与当前草稿一致时，通过版本面板提交；也可以让 AI 调用提交版本工具。
4. 在版本列表选择一个历史版本查看地图。
5. 返回当前地图继续工作，或确认将历史版本恢复为当前草稿。

历史视图为稳定的只读参考。恢复操作以当前草稿版本为基础，并保留已有历史；恢复后可继续修改、预览和提交。

任务记录、已受理消息和已提交版本保存在本地。应用重新打开后可以继续查看项目历史；上次执行中断的任务会标明状态，便于检查现有草稿并明确提出下一步需求。

## 9. 建立和复用 CARTOGRAPHY.md

`CARTOGRAPHY.md` 是地图设计规范，描述颜色、字体、线宽、尺寸、透明度、视觉层级和尺度策略。为系列地图选用同一套规范，可以保持一致的视觉语言。

### 获取规范

制图规范库提供以下入口：

- 上传现有 `CARTOGRAPHY.md`。
- 从在线文档地址导入。
- 从已有地图样式文件或在线 Style 提取规范，并查看生成报告。
- 提交设计简报，让 AI 创建规范。
- 选择内置的 Quiet Atlas 预设。

### 编辑与保存

打开规范后可以预览文档，使用 agent 继续修改，在文档编辑器中查看会话历史，并使用地图预览检查设计方向。生成的草稿经过格式检查，确认后保存到规范库。

规范和样式提取报告可以下载为 `CARTOGRAPHY.md`、`INIT_REPORT.md` 和 `INIT_REPORT.json`，便于复用和审阅。库中的“使用”操作会带着规范选择返回首页，随后创建新地图项目。

项目创建时保存所选规范的完整快照。这样，项目的会话、地图检查和历史依据都能引用当时选定的设计文档。更新规范库后，新建项目可选择新版，已有项目保留清晰的设计来源。

## 10. 调整 API 执行预算

在设置中选择 API Model 后，可以调整执行预算。它决定每轮任务可使用的模型步骤、工具调用次数和单次输出长度。

| 设置 | 默认值 | 应用配置范围 | 使用含义 |
| --- | --- | --- | --- |
| 模型步骤 `maxSteps` | 48 | 1–128 | 模型生成和工具交互的轮数预算 |
| 工具调用 `maxToolCalls` | 192 | 1–512 | 本轮工具调用总预算 |
| 地图编辑输出 `maxOutputTokens` | 16,384 | 256–131,072 | 每次地图模型调用的输出预算 |
| 规范生成输出 `cartographyMaxOutputTokens` | 32,768 | 256–131,072 | 每次制图规范模型调用的输出预算 |

按所选模型提供的输出容量设置 token 预算，并结合任务规模和费用选择数值。大型风格调整可以按“图层检查 → 配色 → 道路 → 标签 → 验证”的顺序拆分。

工具结果会记录明确的成功与失败状态。达到预算或任务中断时，可以检查已保存草稿，随后发送“根据当前状态继续完成剩余步骤”，让下一轮从可见成果开始。

## 11. 使用 md 命令行

`md` 与 Web、桌面端操作同一个 daemon，适合脚本化创建地图、查询进度和管理运行。

### 11.1 连接与查询

```bash
export MAP_DESIGN_DAEMON_URL="http://127.0.0.1:7456"
md status --json
md doctor --json
md agents list --json
md project list --json
md config get --json
```

`status` 和 `doctor` 查询 daemon 健康状态。所有命令也可以使用 `--daemon-url` 指定服务地址。

### 11.2 创建项目并提交首轮需求

下面示例使用已检测可用的 `codex`；可替换为你的运行时 ID。

```bash
md project create \
  --name "城市步行底图" \
  --source-url "https://demotiles.maplibre.org/style.json" \
  --runtime codex \
  --prompt-file - \
  --json <<'PROMPT'
设计一张清晰的城市步行底图，突出步行路线、公园和水系。
完成后检查道路与文字层级，并生成地图预览。
PROMPT
```

`--prompt-file` 也可以指向本地 UTF-8 文件。可选参数 `--model`、`--reasoning` 和 `--service-tier` 对应运行时提供的模型选项。

### 11.3 在现有会话继续执行

先设置目标项目和会话 ID：

```bash
project_id="填入项目ID"
conversation_id="填入会话ID"
md project get "$project_id" --json

curl --fail --silent --show-error \
  "$MAP_DESIGN_DAEMON_URL/api/map-design/projects/$project_id/conversations"

curl --fail --silent --show-error \
  "$MAP_DESIGN_DAEMON_URL/api/map-design/projects/$project_id/conversations/$conversation_id/runtime"
```

从会话列表取得 `conversationId`，从运行时响应读取 `runtime.revision`，填入下一条命令。该修订号对应会话的运行时选择；地图草稿有自己的独立版本号。

```bash
runtime_revision="填入runtime.revision的整数值"
md run start \
  --project-id "$project_id" \
  --conversation-id "$conversation_id" \
  --runtime-revision "$runtime_revision" \
  --prompt-file - \
  --json <<'PROMPT'
检查当前草稿，将公园填充调整得更柔和，再验证并生成预览。
PROMPT
```

保存返回的 `runId`，用于查询状态或停止运行：

```bash
run_id="填入返回的runId"
md run status "$run_id" --json
md run cancel "$run_id" --json
```

### 11.4 项目和配置操作

```bash
md project get "$project_id" --json
md project retry-import "$project_id" --json
md config get apiExecution --json
md config set customInstructions "优先保持图层语义清晰，完成修改后验证并预览。"
```

项目列表也提供删除操作；清理确定需要移除的项目时，可使用 `md project delete "$project_id" --json`。

### 11.5 地图工具与集成

原生 agent 工具、HTTP 工具接口和 MCP 共用地图领域操作。集成程序可以在 daemon 提供的项目和运行授权下使用以下工具：

| 工具 | 用途 |
| --- | --- |
| `map_get_context` | 获取地图上下文、当前版本和设计依据 |
| `map_inspect` | 查看地图、数据源和目标图层，按需选择字段 |
| `map_search_layers` | 查找需要修改的图层 |
| `map_apply_transaction` | 在同一事务中应用一批地图修改 |
| `map_update_semantics` | 更新地图语义信息 |
| `map_validate` | 验证当前地图 |
| `map_render_preview` | 请求渲染预览 |
| `map_commit_revision` | 根据验证与预览结果提交版本 |
| `map_discard_draft` | 将草稿恢复到已提交状态 |

`md tool <工具名> --input <JSON文件或-> --json` 提供命令行调用形式。工具授权由宿主注入 `MAP_DESIGN_DAEMON_URL` 和 `MAP_DESIGN_TOOL_TOKEN`，写入参数遵循当前版本和幂等键约定。集成细节参见[技能协议](skills-protocol.md)与[地图工具效率约定](map-tool-efficiency.md)。

## 12. 数据保存与日常维护

`MAP_DESIGN_DATA_DIR` 指定本地数据根目录，包含数据库、项目文件、配置、运行记录和 agent 状态。日志、缓存和 Electron 用户数据还可能位于启动工具管理的其他目录。源码 daemon 的默认值为启动工作目录下的 `.map-design`；开发工具和桌面启动器可为各自环境指定数据目录。

需要明确指定开发环境数据位置时，可在启动前设置：

```bash
export MAP_DESIGN_DATA_DIR="$HOME/MapDesignData"
pnpm tools-dev start
```

`.map-design-skills/` 是 agent 使用的技能工作副本，可以在相关任务停止后清理，后续运行会重新生成。`.map-design/` 则可能包含项目、会话和未保存的规范草稿，删除它会重置对应本地数据。详见[数据保存与清理](local-data.md)。

备份时先正常停止应用及 daemon，再复制完整数据目录。保留目录内配置文件的访问权限，让项目资料和本地凭据一起得到妥善保存。

| 需要处理的情况 | 可采取的操作 |
| --- | --- |
| 确认服务状态 | `pnpm tools-dev status`、`md status --json` |
| 查看执行线索 | 打开会话工具记录，配合 `pnpm tools-dev logs` |
| 核对模型连接 | 在已保存模型卡片上运行“测试连接” |
| 重新导入地图 | 首页重试入口或 `md project retry-import` |
| 队列暂停 | 检查上一轮结果、编辑待发送需求，再继续发送 |
| 继续中断的任务 | 查看当前草稿与历史消息，明确提交剩余工作 |
| 查看运行的最终状态 | 使用 `md run status`，或重新打开项目读取本地记录 |
| 需要回到先前风格 | 从版本面板选择历史版本并恢复为当前草稿 |

## 13. 一次典型的制图交付

1. 在规范库选定或生成项目的 `CARTOGRAPHY.md`。
2. 首页预览地图源，创建项目并填写整体目标。
3. 让 AI 检查图层结构，完成第一轮主题调整。
4. 在队列中依次安排道路、标签和局部优化。
5. 用评论定位具体要素，用截图补充视觉要求。
6. 使用拾取编辑或代码视图做精细调整。
7. 验证当前草稿，观察预览，并提交阶段版本。
8. 在项目中保留会话、设计规范和版本记录，便于继续迭代。
