# 测试效率与确定性

MapDesign 测试应在能证明行为的最窄层运行，并保持每个用例独立。

- 等待可观察的完成信号，例如响应成功、持久化状态、SSE 结束或进程退出；不要用固定 sleep 猜测完成时间。
- polling、retry、backoff、debounce、TTL 等可控计时逻辑使用虚拟时钟，并断言边界两侧。
- 测试各自创建数据、配置和运行时；按后创建先关闭的顺序释放资源。
- 浏览器测试只在跨越真实 web/daemon 边界时使用，且通过 `e2e` 的共享生命周期工具启动隔离的 `tools-dev` 运行时。
- 修复可观察缺陷时，先写能失败的聚焦用例；不要以增大超时或串行化替代修复。

完成变更时运行相关聚焦测试、相应包的检查，以及根目录 `pnpm guard` 和 `pnpm typecheck`。
